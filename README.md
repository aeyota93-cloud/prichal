# Причал

[![ci](https://github.com/aeyota93-cloud/prichal/actions/workflows/ci.yml/badge.svg)](https://github.com/aeyota93-cloud/prichal/actions/workflows/ci.yml)
[![Лицензия: MIT](https://img.shields.io/badge/лицензия-MIT-blue.svg)](LICENSE)

Панель для своего Linux-сервера с Docker, на русском. Показывает, что работает
на сервере, даёт перезапустить или остановить контейнер, посмотреть журнал,
поставить обновления и присылает в Telegram сообщения, если что-то сломалось.

Это один маленький образ: около 10 МБ на диске, в работе обычно 5-10 МБ памяти.
Базы данных и внешних сервисов нет. Проект открытый, весь код лежит в этом
репозитории, и перед установкой его можно прочитать (см.
[«Как устроена безопасность»](#как-устроена-безопасность)).

## Что умеет

Разделы панели переключаются в меню слева, на телефоне — в строке сверху.
Кнопка «Назад» в браузере возвращает на предыдущий раздел.

- **Обзор.** Одна фраза о том, всё ли в порядке («Всё работает спокойно» или
  что именно сломалось), процессор, память и диск в одну линию, плитки
  контейнеров, строка уведомлений в Telegram (подключить, изменить или
  отключить бота можно тут же) и лента «Что происходило»: сбои и
  восстановления контейнеров, перезагрузки сервера, нехватка места и памяти,
  действия из панели (в том числе неудачные), итоги установки обновлений.
  Видны последние 6 событий, кнопка «Показать все» открывает до 30. Лента
  ведётся, даже если Telegram не настроен, и переживает перезапуск панели.
- **Контейнеры.** Состояние, нагрузка на процессор и память с графиком за
  последние минуты, журнал, фильтр «VPN и прокси / Приложения». Кнопки:
  перезапустить, остановить, запустить и журнал, а редкие действия (пауза,
  принудительная остановка) спрятаны за кнопкой «Ещё». Перед опасным действием
  панель переспрашивает и пишет, что именно перестанет работать; если вы
  останавливаете VPN, через который подключены, подсказывает команду для
  запуска по SSH.
- **Подключения.** Появляется, если на сервере стоит
  [Amnezia VPN](https://amnezia.org): кто из клиентов AmneziaWG, WireGuard и
  OpenVPN сейчас на связи, когда был последний раз, сколько трафика. Для прокси
  Telegram (telemt): сколько устройств на каждой ссылке и с каких адресов.
  Ссылки и клиентов VPN можно подписать («Мама», «Телефон мамы»). Подпись
  привязана к имени клиента в Amnezia: если переименовать клиента там, подпись
  пропадёт. Добавлять и удалять клиентов нужно в приложении Amnezia.
- **Обновления.** Одна кнопка «Проверить обновления» проверяет всё сразу, под
  ней видно, как давно была проверка.
  - Пакеты системы: список с галочками, установка выбранного с журналом в
    реальном времени. Рекомендуемое выбрано заранее: всё, кроме Docker (его
    обновление ненадолго останавливает все контейнеры и панель). Нужна
    перезагрузка — панель говорит об этом, и перезагрузить сервер можно кнопкой
    в блоке «Сервер» внизу раздела.
  - Приложения на docker compose: панель узнаёт, вышла ли новая версия образа
    (Docker Hub, GitHub, Quay и другие открытые реестры), и обновляет одной
    кнопкой, перед этим сохранив копию данных.
  - Приложения, собранные на сервере из git (в том числе сам Причал): панель
    проверяет репозиторий, показывает новые коммиты и обновляет кнопкой.
- **Боковое меню.** У пункта «Обновления» стоит число того, что можно
  обновить; оно жёлтое, если есть обновления безопасности или серверу нужна
  перезагрузка, а при наведении показывает разбивку. Внизу кнопка перезагрузки
  сервера (на телефоне она находится внизу раздела «Обновления») и выход.
- **Образы.** Сколько места занимают, какие не нужны. Очистка удаляет
  ненужные образы и кэш сборки и пишет, сколько места освободилось на самом
  деле. Образ `alpine`, через который панель выполняет команды на сервере,
  она не трогает.
- **Telegram.** Сообщения, если контейнер упал или крутится в перезапусках,
  сервер перезагрузился, кончается место или память. По воскресеньям сводка
  доступных обновлений. Бота подключают в самой панели, без правки файлов.

Интерфейс только на русском.

## Что нужно

- Сервер с Linux и доступом по SSH. Подойдёт любой VPS на KVM, VMware или
  Hyper-V, а также свой компьютер. На дешёвых VPS на OpenVZ или LXC Docker
  часто урезан, и раздел «Обновления» там может не заработать.
- Процессор amd64 (x86_64) или arm64.
- Хотя бы 1 ГБ памяти, чтобы собрать панель. Если памяти меньше, понадобится
  подкачка, см. [«Если что-то не работает»](#если-что-то-не-работает).
- Docker 20.10 или новее с Docker Compose v2 и git. Как их поставить, описано
  ниже.

Обновление пакетов умеет apt (Debian, Ubuntu), dnf и yum (Fedora, RHEL, Rocky,
Alma) и apk (Alpine). На других системах раздел честно скажет, что менеджер
пакетов не поддерживается, а всё остальное будет работать.

## Установка

Все команды ниже выполняются на сервере от root. Если вы заходите обычным
пользователем, перед началом выполните `sudo -i`.

### Шаг 1. Подключитесь к серверу

С Windows 10/11, macOS или Linux откройте терминал (на Windows это PowerShell)
и выполните:

```bash
ssh root@адрес-сервера
```

Адрес сервера и пароль root обычно приходят в письме от хостинга.

### Шаг 2. Поставьте Docker и git

Сначала проверьте, может быть, всё уже стоит:

```bash
docker --version
docker compose version
git --version
```

Если все три команды ответили версиями (Docker 20.10 или новее), переходите к
шагу 3. Иначе поставьте недостающее.

**Ubuntu, Debian, Fedora:**

```bash
curl -fsSL https://get.docker.com | sh
```

Это официальный скрипт установки Docker, он ставит и Docker, и Docker Compose.
Затем git: на Ubuntu и Debian `apt-get install -y git`, на Fedora
`dnf install -y git`.

**Rocky, Alma, CentOS Stream:**

```bash
dnf install -y git dnf-plugins-core
dnf config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
dnf install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
systemctl enable --now docker
```

**Alpine:**

```bash
apk add git docker docker-cli-compose
rc-update add docker default
service docker start
```

После установки ещё раз выполните три команды проверки из начала шага.

### Шаг 3. Скачайте Причал

Причал ставится в папку `/opt/prichal`. Репозиторий открытый, ключи и пароли
от GitHub не нужны:

```bash
git clone https://github.com/aeyota93-cloud/prichal.git /opt/prichal
```

Если вы сделали свой форк, подставьте его адрес. Для закрытого форка серверу
понадобится deploy-ключ с доступом только на чтение (на GitHub:
**Settings → Deploy keys**), а клонировать нужно по SSH-адресу
`git@github.com:ВАШ-АККАУНТ/prichal.git`.

### Шаг 4. Запустите установку

```bash
cd /opt/prichal
./install.sh
```

Что сделает скрипт:

1. Проверит, что Docker работает.
2. Создаст файл настроек `/opt/prichal/.env` (его может читать только root).
3. Соберёт образ панели и запустит её. В первый раз Docker скачает
   инструменты Go и соберёт программу, это занимает 1-3 минуты. После сборки
   скрипт удалит временные файлы, чтобы они не занимали место на диске.
4. Проверит, что панель отвечает, и напишет, как к ней подключиться:

   ```
   === Причал работает на 127.0.0.1:9443 ===
   Откройте на своём компьютере SSH-туннель:
     ssh -N -L 9443:127.0.0.1:9443 root@203.0.113.10
   и зайдите в браузере на http://localhost:9443
   При первом входе панель попросит придумать пароль.
   Уведомления в Telegram подключаются в самой панели: Обзор → Уведомления → Подключить.
   ```

Проверить, что контейнер запущен, можно так:

```bash
docker ps --filter name=prichal
```

В столбце `STATUS` должно быть `Up`. Журнал панели: `docker logs prichal`.

### Шаг 5. Откройте панель со своего компьютера

Панель слушает только `127.0.0.1` на сервере, то есть из интернета её не
видно. Заходить к ней нужно через SSH-туннель: он пробрасывает порт сервера
на ваш компьютер по уже защищённому SSH-соединению. Открывать порты в
файрволе не нужно.

**Вручную (любая система).** Откройте терминал на своём компьютере:

```bash
ssh -N -L 9443:127.0.0.1:9443 root@адрес-сервера
```

Введите пароль. Терминал ничего не напишет и будет просто ждать: это значит,
что туннель работает. Откройте в браузере http://localhost:9443. Пока вы
работаете с панелью, окно терминала не закрывайте.

**Первый вход.** Панель попросит придумать пароль: не короче 8 символов,
дважды. Она хранит только его хэш (зашифрованный отпечаток), а не сам пароль.
Вход запоминается на 30 дней на каждом устройстве и не сбрасывается при
обновлении панели. Если пароль задан в `.env` (`PRICHAL_PASSWORD`), панель
сразу спросит его. Вместо root подойдёт любой
пользователь, которому разрешён вход по SSH.

**Ярлык для Windows.** В папке `clients` лежит `prichal-tunnel.cmd`.

1. Скачайте его на компьютер: по
   [прямой ссылке](https://raw.githubusercontent.com/aeyota93-cloud/prichal/main/clients/prichal-tunnel.cmd)
   (правый щелчок, «Сохранить как…») или с сервера командой
   `scp root@адрес-сервера:/opt/prichal/clients/prichal-tunnel.cmd .`
2. Откройте файл в Блокноте, например перетащите его в окно Блокнота.
3. В строке `set "SERVER=root@АДРЕС-СЕРВЕРА"` впишите адрес своего сервера и
   сохраните файл.
4. Запускайте двойным щелчком. Откроется чёрное окно, введите в нём пароль.
   Браузер откроет панель сам. Пока работаете, окно не закрывайте.

Если на сервере есть другие программы, которые слушают только `127.0.0.1`
(например, n8n на порту 5678), их можно открыть через тот же туннель: впишите
порты в строку `set "EXTRA=5678"` через пробел.

**Ярлык для macOS и Linux.** Скачайте
[`clients/prichal-tunnel.sh`](https://raw.githubusercontent.com/aeyota93-cloud/prichal/main/clients/prichal-tunnel.sh)
и запускайте:

```bash
chmod +x prichal-tunnel.sh
./prichal-tunnel.sh root@адрес-сервера            # только панель
./prichal-tunnel.sh root@адрес-сервера 9443 5678  # панель и порт 5678
```

Браузер откроется сам, как только туннель заработает. Выйти: Ctrl+C.

### Шаг 6. Уведомления в Telegram (по желанию)

Всё делается в панели, на сервере ничего править не нужно.

1. У вас в Telegram должно быть имя пользователя (@username). Оно задаётся в
   настройках Telegram, в пункте «Имя пользователя». Если его нет, придумайте:
   без него бот не сможет понять, что пишете именно вы.
2. Напишите [@BotFather](https://t.me/BotFather) команду `/newbot`, придумайте
   боту название и имя. В ответ придёт токен вида
   `1234567890:AAE...`. Никому его не показывайте.
3. В панели откройте «Обзор», строку «Telegram», нажмите «Подключить». Вставьте
   токен и своё имя пользователя (без `@`), нажмите «Подключить». Панель
   проверит токен у Telegram.
4. Откройте своего бота (в окне есть кнопка) и нажмите **Start**. Через
   несколько секунд бот пришлёт приветствие, а окно само покажет «Подключено».
   Писать он будет только вам, на сообщения других людей он не реагирует.

Там же бота можно изменить (другой ник или токен), проверить кнопкой «Прислать
проверку» и отключить. Токен хранится в томе панели (`/data`, права 0600) и в
браузер, журнал и ленту событий не попадает.

**Настройки из панели главнее `.env`.** Если вы подключили бота раньше через
`TG_TOKEN` и `TG_USERNAME` в `.env`, он продолжит работать без изменений. После
первого сохранения в панели строки `TG_` из `.env` больше не используются, их
можно удалить. Если отключить бота в панели, он останется выключенным, даже если
в `.env` что-то записано.

Серверу нужен доступ к `api.telegram.org`. У некоторых хостингов он закрыт,
тогда уведомления не придут, а в журнале `docker logs prichal` будут ошибки
отправки.

## Настройки

Все настройки лежат в `/opt/prichal/.env`. После правки выполните
`cd /opt/prichal && docker compose up -d`, и панель перезапустится с новыми
значениями.

| Переменная | Что задаёт | По умолчанию |
|---|---|---|
| `PRICHAL_PORT` | порт панели на сервере | `9443` |
| `LABEL` | подпись сервера на «Обзоре» и в заголовке вкладки браузера | имя сервера (hostname) |
| `PRICHAL_PASSWORD` | пароль для входа; главнее придуманного при первом входе | пусто, пароль придумывается при первом входе |
| `ALLOWED_HOSTS` | домены для доступа через обратный прокси, через запятую | пусто |
| `TG_TOKEN` | токен Telegram-бота. Проще подключить бота в панели; настройки панели главнее этих строк | пусто, уведомления выключены |
| `TG_USERNAME` | ваше имя пользователя в Telegram, без `@` (так же, главнее настройки панели) | пусто |
| `TZ` | часовой пояс сообщений и воскресной сводки, например `Asia/Yekaterinburg` | московское время |

Если поменяли `PRICHAL_PORT`, в команде туннеля меняется правая часть:
`ssh -N -L 9443:127.0.0.1:НОВЫЙ-ПОРТ root@адрес-сервера`.

## Доступ по домену (по желанию)

Если туннель неудобен, панель можно открыть по адресу вроде
`https://panel.example.com` через обратный прокси на том же сервере. В этом
случае пароль обязателен: без него панель откажется работать.

1. Направьте домен на IP сервера (A-запись у регистратора домена).
2. В `/opt/prichal/.env` задайте пароль и домен:

   ```
   PRICHAL_PASSWORD=длинный-случайный-пароль
   ALLOWED_HOSTS=panel.example.com
   ```

   и выполните `cd /opt/prichal && docker compose up -d`.
3. Настройте прокси. Для [Caddy](https://caddyserver.com), установленного на
   сервере, достаточно двух строк в `/etc/caddy/Caddyfile`, сертификат HTTPS он
   получит сам:

   ```
   panel.example.com {
       reverse_proxy 127.0.0.1:9443
   }
   ```

   Для Nginx важно передать исходный адрес и протокол:

   ```nginx
   location / {
       proxy_pass http://127.0.0.1:9443;
       proxy_set_header Host $host;
       proxy_set_header X-Forwarded-Proto $scheme;
   }
   ```

Порт 9443 в `compose.yaml` при этом по-прежнему привязан к `127.0.0.1`:
снаружи панель доступна только через прокси.

## Обновление Причала

```bash
cd /opt/prichal
git pull
./install.sh
```

Настройки в `.env`, подписи ссылок, привязка Telegram и лента событий
сохраняются. Сборка займёт 1-3 минуты, панель пропадёт на пару секунд.

То же можно сделать из самой панели: раздел «Обновления», строка «Причал» в
блоке «Приложения». Когда в репозитории появляются новые коммиты, там видно
их список и кнопку «Обновить». Панель делает `git pull --ff-only`, пересобирает
образ и перезапускается; если новая версия не поднялась, возвращает прежний
коммит. Нужно только, чтобы на сервере был `git`: репозиторий открытый, ключи
не нужны (для закрытого форка у root должен быть deploy-ключ в `~/.ssh`).
Панель проверяет обновления, когда её открывают (результат помнит 6 часов), и по
кнопке «Проверить обновления».

## Удаление

```bash
cd /opt/prichal
docker compose down -v --rmi all   # контейнер, его настройки и образ
cd / && rm -rf /opt/prichal /var/lib/prichal
```

Копии данных приложений, которые Причал делал перед обновлениями, лежат в
`/var/backups/prichal`. Удалите их отдельно, если они не нужны:
`rm -rf /var/backups/prichal`.

## Как устроена безопасность

Причал управляет Docker, ставит пакеты и перезагружает сервер, то есть по сути
имеет права root. Поэтому:

- По умолчанию он слушает только `127.0.0.1`, и попасть в него можно только
  через SSH. Вход всё равно по паролю: так панель защищена и от ошибок в
  настройке прокси, и от других программ на самом сервере.
- Пока пароля нет, панель показывает только страницу, где его придумывают, и
  только при заходе через туннель (`localhost`, без признаков прокси).
- Если порт панели опубликовать на внешнем адресе или задать `ALLOWED_HOSTS`,
  а пароль не задать в `.env`, панель заблокируется и объяснит, что сделать.
- Пароль проверяется с защитой от подбора: после 10 неудачных попыток за
  5 минут вход временно закрывается.
- Другие сайты, открытые в том же браузере, не могут ничего сделать от вашего
  имени: панель проверяет заголовки `Host` и `Origin`, каждое действие требует
  особый заголовок, на странице действует строгая политика CSP.
- Ключи VPN, ссылки прокси с секретами и токен бота в браузер не передаются.
- Копии данных приложений в `/var/backups/prichal` может читать только root.
- Вспомогательный образ `alpine` закреплён по контрольной сумме (digest):
  подменить его через Docker Hub не получится.
- Кнопка «Обновить» у Причала собирает код из git-репозитория, откуда он был
  установлен, то есть из этого. Значит, кто может отправить коммит в
  репозиторий, тот после обновления получит доступ к серверу. Читайте список
  новых коммитов в панели перед нажатием. Если вы не готовы доверять автору,
  сделайте форк, ставьте из него и обновляйте только то, что прочитали сами.
- Код открытый: проверить, что именно запускается на сервере, можно до
  установки. Сборку и проверки (`go vet`, тесты, `govulncheck`, `shellcheck`)
  GitHub запускает публично, результат виден на вкладке Actions.

**Нашли уязвимость?** Не пишите о ней в публичных Issues. Откройте вкладку
**Security** репозитория и нажмите **Report a vulnerability**, чтобы сообщение
увидел только автор.

Команды на самом сервере (пакеты, перезагрузка, копии данных) Причал выполняет
через короткоживущие вспомогательные контейнеры `prichal-host-*` на образе
`alpine`. Сами команды лежат в папке `scripts/` и встроены в программу. Долгие задачи на серверах с systemd запускаются как отдельные службы
с именами `prichal-*`, поэтому не обрываются, даже если посреди установки
обновится сам Docker. Без systemd (например, на Alpine) задача идёт во
вспомогательном контейнере, и обновление Docker её прервёт: Docker там лучше
обновлять из терминала. Журналы задач лежат в `/var/lib/prichal/tasks/`.

## Копии данных и откат приложения

Перед обновлением приложения Причал может сохранить его тома Docker. Галочка
«копия данных» включена по умолчанию, если тома занимают меньше 1 ГБ. Копии
лежат в `/var/backups/prichal/<проект>/<дата>/`, хранятся 5 последних. Там же
копия файла docker-compose на момент обновления.

Вернуть данные из копии:

```bash
cd /папка/проекта        # где лежит docker-compose.yml приложения
docker compose stop <сервис>
docker run --rm -v <том>:/data -v /var/backups/prichal/<проект>/<дата>:/backup:ro alpine \
  sh -c 'find /data -mindepth 1 -delete && tar xzf /backup/<том>.tar.gz -C /data'
docker compose up -d <сервис>
```

Так вернутся данные, но версия программы останется новой. Чтобы вернуть и
версию, укажите в docker-compose старый тег образа (например,
`n8nio/n8n:2.33.7` вместо `n8nio/n8n:latest`) и выполните
`docker compose up -d`.

После обновления Причал ждёт, пока приложение запустится: до двух минут,
а если у контейнера есть healthcheck, то пока он не станет healthy. Если
приложение не заработало, обновление считается неудачным. Контейнер при этом
остаётся, чтобы посмотреть его журнал, а в журнале задачи Причал пишет ID
образа, который работал раньше. Пока вы не очистили образы, его можно вернуть:
`docker tag <ID> <имя образа>` и `docker compose up -d`. Данные при этом
восстанавливайте из копии (см. выше): новая версия могла их изменить.

При обновлении из git Причал не стирает ваши правки файлов проекта на
сервере: если новая версия не собралась, он возвращает прежний коммит, а ваши
изменения остаются на месте.

Образы с тегом-версией (`postgres:16.4`) Причал до новой версии не обновляет:
он проверяет только, не пересобрали ли тот же тег. Чтобы перейти на новую
версию, поменяйте тег в docker-compose.

## Если что-то не работает

**`./install.sh: Permission denied`.** Запустите так: `sh install.sh`.

**Сборка обрывается со словами `killed` или `signal: killed`.** Не хватило
памяти. Добавьте подкачку на 2 ГБ и запустите `./install.sh` снова:

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

**Туннель пишет `Address already in use`.** Порт 9443 на вашем компьютере уже
чем-то занят, например вторым окном туннеля. Возьмите другой порт слева:
`ssh -N -L 19443:127.0.0.1:9443 root@адрес-сервера` и откройте
http://localhost:19443.

**Туннель пишет `administratively prohibited`.** На сервере запрещён проброс
портов. В `/etc/ssh/sshd_config` поставьте `AllowTcpForwarding yes` и
выполните `systemctl restart ssh` (на Rocky и Alma: `systemctl restart sshd`).

**Браузер показывает `forbidden host`.** Панель открыли не по `localhost`, а
по IP или домену. Через туннель открывайте http://localhost:9443. Для домена
пропишите его в `ALLOWED_HOSTS` и задайте пароль.

**Страница «Причал заблокирован».** Панель доступна снаружи без пароля.
Задайте `PRICHAL_PASSWORD` в `.env` и выполните `docker compose up -d`.

**Забыли пароль.** Если он придуман при первом входе, на сервере выполните:

```bash
docker exec prichal /prichal reset-password
docker restart prichal
```

и придумайте новый. Все входы на устройствах при этом сбросятся. Если пароль
задан в `.env` (`PRICHAL_PASSWORD`), посмотрите или поменяйте его там и
выполните `cd /opt/prichal && docker compose up -d`.

**«Пароль можно задать только через SSH-туннель».** Пароль при первом входе
принимается, только если панель открыта через туннель по `localhost`. Через
домен или прокси сначала задайте `PRICHAL_PASSWORD` в `.env`.

**Раздел «Обновления» пишет ошибку.** Причалу нужно запускать на сервере
привилегированные контейнеры и скачать образ `alpine` из Docker Hub. Это не
получится, если у сервера нет выхода в интернет, если Docker запущен без прав
root (rootless) или сервер работает на OpenVZ/LXC.

**Бот в Telegram молчит.** Откройте «Обзор» и нажмите «Настроить» в строке
Telegram: окно покажет, чего не хватает. Если там «ждём Start», откройте бота и
нажмите Start. Проверьте, что ник в окне совпадает с вашим именем
пользователя в Telegram, и нажмите «Прислать проверку». Журнал:
`docker logs prichal 2>&1 | grep -i telegram`.

**Нет раздела «Подключения».** Он появляется, только если на сервере
работают контейнеры Amnezia VPN.

## Разработка

Нужен Go 1.26. Панель можно запускать у себя, подключив её к Docker сервера
через SSH. Такой туннель даёт полный доступ к Docker сервера, после работы
закройте его.

```bash
ssh -N -L 127.0.0.1:23750:/var/run/docker.sock root@адрес-сервера
DOCKER_HOST=tcp://127.0.0.1:23750 LISTEN=127.0.0.1:9444 go run .
```

Проверки перед коммитом: `gofmt -l .`, `go vet ./...`, `go test ./...`. GitHub
при каждой отправке запускает их же (тесты с `-race`), а ещё `govulncheck`
и `shellcheck` для скриптов. Тесты скриптов из `scripts/` запускают их с
поддельными `git` и `docker`, поэтому на Windows пропускаются.

Устройство кода: `main.go` запускает сервер, `http.go` защищает запросы,
`auth.go` отвечает за пароль, `api_*.go` и `images.go` за разделы панели,
`scripts/` хранит команды для сервера. Интерфейс в `web/` разбит на модули
без сборщика: `app.js` запускает страницу, остальные файлы — по разделам. При каждом теге `v*` GitHub собирает
образ под amd64 и arm64 и публикует его в `ghcr.io/aeyota93-cloud/prichal`.

### Если хотите помочь

Нашли ошибку или есть идея: заведите [Issue](https://github.com/aeyota93-cloud/prichal/issues)
и опишите, что ожидали и что получилось (версию системы и кусок журнала
`docker logs prichal` приложите, но без токенов и паролей). Правки принимаются
через pull request. Перед отправкой выполните три проверки, описанные выше.
Правила проекта: в `web/` без сборщика и сторонних библиотек, без
`innerHTML` для данных и атрибутов `style=` (мешает политика CSP), в Go только
стандартная библиотека.
