# Настройки и обслуживание

[Вернуться к установке](../README.md#установка)

## Настройки

Порт, подпись сервера и переменные окружения задаются в `/opt/prichal/.env`.
Пароль, придуманный при первом входе, подписи клиентов, события и настройки
Telegram из панели хранятся отдельно — в томе Docker `prichal-data`.
Обычное обновление этот том не удаляет.

| Переменная в .env | Что задаёт | По умолчанию |
|---|---|---|
| `PRICHAL_PORT` | Порт панели на сервере | `9443` |
| `LABEL` | Подпись сервера в обзоре и заголовке вкладки | Имя хоста |
| `PRICHAL_PASSWORD` | Пароль; имеет приоритет над придуманным в панели | Пусто, пароль задаётся при первом входе |
| `ALLOWED_HOSTS` | Домены для доступа через прокси, через запятую | Пусто |
| `TG_TOKEN`, `TG_USERNAME` | Токен бота и имя получателя без `@` | Пусто |
| `TZ` | Часовой пояс сообщений, например `Asia/Yekaterinburg` | Московское время |

После изменения `.env` выполните **на сервере**:

```sh
cd /opt/prichal
docker compose up -d
```

После первого сохранения настроек Telegram в панели используются они,
а не `TG_TOKEN` и `TG_USERNAME` из `.env`. Если отключить бота в панели,
наличие токена в `.env` не включит его обратно.

Токен из панели хранится в файле с правами `0600` внутри `/data`.
В ответах API он не возвращается; ошибки Telegram очищаются от токена.
Серверу нужен доступ к `api.telegram.org`.

## Другой порт туннеля

Если 9443 занят **на компьютере**, выберите другой локальный порт:

```sh
ssh -N -L 127.0.0.1:19443:127.0.0.1:9443 -o ExitOnForwardFailure=yes root@АДРЕС-СЕРВЕРА
```

Открывать нужно `http://localhost:19443`. Порт панели на сервере остаётся 9443.
Если вы меняли `PRICHAL_PORT` в `.env`, замените последний порт в команде.

Другие сервисы можно открыть через тот же туннель. В Windows-ярлыке
впишите их порты через пробел в `set "EXTRA=5678 10800"`.
Для скрипта macOS/Linux:

```sh
./prichal-tunnel.sh root@АДРЕС-СЕРВЕРА 9443 5678 10800
```

## Доступ по домену

По умолчанию используйте SSH-туннель. Для доступа по домену понадобится
обратный прокси с HTTPS на том же сервере и пароль в `.env`.

1. Направьте домен на сервер через DNS.
2. Задайте в `/opt/prichal/.env`:

   ```dotenv
   PRICHAL_PASSWORD=ЗАМЕНИТЕ-НА-СВОЙ-ДЛИННЫЙ-ПАРОЛЬ
   ALLOWED_HOSTS=panel.example.com
   ```

3. Выполните `cd /opt/prichal && docker compose up -d`.
4. Настройте прокси. Пример блока для [Caddy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy):

   ```caddyfile
   panel.example.com {
       reverse_proxy 127.0.0.1:9443
   }
   ```

   Для Nginx в конфигурации HTTPS-сайта:

   ```nginx
   location / {
       proxy_pass http://127.0.0.1:9443;
       proxy_set_header Host $host;
       proxy_set_header X-Forwarded-Proto $scheme;
   }
   ```

Примеры предполагают, что прокси установлен и настроен на сервере.
Для Nginx сертификат и блок HTTPS нужны отдельно. Порт Причала в
`compose.yaml` оставьте на `127.0.0.1`; публиковать его наружу не требуется.

## Сброс пароля

Если пароль придуман при первом входе, выполните **на сервере**:

```sh
docker exec prichal /prichal reset-password
docker restart prichal
```

Затем откройте панель через туннель и задайте новый пароль. Прежние входы
на устройствах сбросятся. Если пароль задан через `PRICHAL_PASSWORD` в `.env`,
измените его там и выполните `cd /opt/prichal && docker compose up -d`.

## Копии данных

При обновлении приложения из реестра можно включить **«копия данных»**.
Она сохраняет именованные тома Docker и копии файлов Compose.
Обычные папки сервера, подключённые в контейнер как bind mount, не копируются.
При обновлении из git этот механизм копирования томов не используется.

Галочка по умолчанию включена, если рассчитанный объём томов не превышает
1 ГБ. Неизвестные размеры в этом расчёте считаются нулевыми, поэтому
проверьте объём и свободное место перед большой копией.
Во время копирования обновляемый сервис остановлен; другие сервисы, которые
пишут в тот же том, Причал не останавливает.

Копии лежат в `/var/backups/prichal/<проект>/<дата>/`. После успешного
обновления остаются пять последних копий проекта.

Восстановление выполняется вручную. Команда ниже **заменяет содержимое тома**
данными из архива. Подставьте настоящие имена сервиса, тома и папки копии;
перед этим сохраните текущие данные, если они нужны:

```sh
cd /ПАПКА-ПРОЕКТА
docker compose stop СЕРВИС
docker run --rm -v ИМЯ-ТОМА:/data -v /var/backups/prichal/ПРОЕКТ/ДАТА:/backup:ro alpine \
  sh -c 'find /data -mindepth 1 -delete && tar xzf /backup/ИМЯ-ТОМА.tar.gz -C /data'
docker compose up -d СЕРВИС
```

Это восстанавливает данные, но не версию программы. Для отката версии
поменяйте тег образа в Compose и запустите сервис заново.

## Если обновление не удалось

Причал проверяет запуск контейнера; при наличии healthcheck ждёт состояния
`healthy`. Это проверка запуска, а не всех функций приложения.

- При обновлении из git скрипт пытается вернуть прежний коммит и пересобрать
  сервис. Правки на сервере не стираются: если они мешают откату, об этом
  будет сообщение в журнале задачи.
- При обновлении образа из реестра ошибка после запуска новой версии оставляет
  новый контейнер для просмотра журнала. ID прежнего образа записывается
  в журнал задачи. Автоматического восстановления данных нет.

Если старый образ ещё не удалён, его можно вернуть командой
`docker tag ID-ПРЕЖНЕГО-ОБРАЗА ИМЯ-ОБРАЗА` и затем `docker compose up -d СЕРВИС`.
Данные восстанавливаются отдельно: новая версия могла их изменить.

Причал сравнивает образ с тем же тегом. Например, `postgres:16.4` сам не
переключится на другой номер версии; для этого нужно изменить Compose.
Проверка реестров рассчитана на доступ без логина.

## Безопасность

Доступ к Docker даёт Причалу права, сопоставимые с root. Пароль панели
обязателен. При доступе по домену или внешнему адресу его нужно заранее
задать в `.env`, иначе панель заблокируется.

Пароль из формы хранится как хэш PBKDF2-SHA256 с солью. После десяти
неудачных входов за пять минут новые попытки временно блокируются.
Запросы проверяются по `Host` и `Origin`, изменения требуют специального
заголовка, а страница использует CSP. Эти меры не заменяют защиту самого SSH
и сервера.

Ключи VPN и секретные ссылки прокси не возвращаются в данных подключений.
IP-адреса устройств Telegram-прокси показываются владельцу панели.
Журналы приложений могут содержать их собственные секреты — учитывайте это,
если собираетесь переслать журнал или сделать скриншот.

Обновление из git запускает код из репозитория установленного приложения.
Если обновляете Причал из этого репозитория, вы доверяете его автору доступ
к серверу. Можно установить свой форк и проверять изменения перед обновлением.
Для закрытого репозитория у root нужен доступ к нему без запроса пароля.

Команды обслуживания выполняются через вспомогательные контейнеры
`prichal-host-*`. Их образ Alpine закреплён по digest.
На серверах с systemd долгие задачи запускаются отдельной службой и могут
пережить перезапуск Docker. Без systemd обновление Docker может прервать
задачу; его лучше выполнять через терминал. Журналы задач:
`/var/lib/prichal/tasks/`.

## Дополнительные ошибки

- `forbidden host`: через туннель открывайте `localhost`. Для домена нужны
  `ALLOWED_HOSTS` и пароль в `.env`.
- «Причал заблокирован»: проверьте пароль и способ публикации порта.
- `administratively prohibited`: SSH-сервер не разрешает проброс портов.
  Проверьте `AllowTcpForwarding` и ограничения используемого ключа.
- Ошибка раздела «Обновления»: нужен доступ в интернет и возможность запускать
  привилегированные контейнеры. Rootless Docker и ограничения OpenVZ/LXC могут
  помешать. На системах без apt, dnf, yum или apk обновление пакетов не поддерживается.
- Нет «Подключений»: контейнер должен распознаваться как поддерживаемый сервис
  Amnezia. Раздел не показывает клиентов произвольного VPN.

## Удаление

Следующие команды удалят Причал **вместе с его настройками, паролем и лентой
событий**. Контейнеры других приложений они не удаляют.

```sh
cd /opt/prichal
docker compose down -v --rmi all
cd /
rm -rf /opt/prichal /var/lib/prichal
```

Копии приложений в `/var/backups/prichal` останутся. Удаляйте их отдельно,
только если они больше не нужны.
