# Прокси Telegram в составе Причала — план (31.10.2026)

Сейчас Причал управляет ссылками чужого прокси: контейнера `amnezia-telemt`, который когда-то
поставило приложение Amnezia (через `docker exec`, `scripts/telemt-api.sh`). Цель — чтобы
Причал умел **сам поставить свой прокси** при установке и полностью им управлять, без Amnezia.

## Как должно быть устроено

1. **Свой сервис в `compose.yaml`**, профиль `proxy` (по умолчанию выключен):
   - образ собирается из официального релиза telemt (`github.com/telemt/telemt`) с **закреплённой
     версией и проверкой sha256** (сейчас Amnezia берёт `latest` без закрепления);
     бинарник статический (musl) → образ `FROM scratch`, как сам Причал;
   - `read_only: true`, данные в томе `prichal-proxy-data` (`config.toml`, кэш);
   - порт клиента настраивается: `PROXY_PORT` (443, если свободен; за nginx — внутренний порт).
2. **Управление по сети, а не через `docker exec`:**
   - отдельная внутренняя сеть Docker `prichal-proxy` между Причалом и прокси;
   - API telemt слушает только в ней, `whitelist` — подсеть этой сети, `auth_header` —
     случайный пароль, который `install.sh` кладёт в том Причала (права 0600);
   - Причал ходит в API по HTTP с этим заголовком. `docker exec` остаётся только для
     «чужого» прокси Amnezia (обратная совместимость).
3. **`install.sh`:** вопрос «Поставить прокси Telegram?» → порт, домен-маскировка
   (`tls_domain`), первая ссылка. Генерация `config.toml` из шаблона; повторный запуск
   ничего не перетирает (секреты пользователей живут в `[access.users]`, их меняет только API).
4. **Интерфейс:** тот же раздел «Подключения» → «Прокси Telegram» (уже сделан). Плюс
   настройки прокси (домен-маскировка, порт) через `PATCH /v1/config`.
5. **Обновление прокси** — во вкладке «Обновления» Причала: новая версия telemt = смена
   закреплённой версии + sha256 в репозитории, `docker compose up -d --build proxy`.

## Перенос прокси Amnezia на этом сервере (без смены ссылок)

Ссылки не меняются, если сохранить: секреты пользователей, `tls_domain`, публичный адрес и
порт ссылок (443 через nginx).

1. Копия `/data` контейнера `amnezia-telemt` (секреты, лимиты, `tlsfront`).
2. Новый `config.toml` Причала: `[access.users]` и лимиты — из старого; `[server]` порт —
   внутренний; `[general.links] public_port = 443`; API — во внутренней сети с паролем.
3. Поднять прокси Причала рядом, проверить ссылку тестовым клиентом.
4. Переключить nginx: `VPN_TELEMT_ADDR` (default в `vpn-sni.conf`) → адрес прокси Причала;
   `nginx -t`, reload (соединения не рвутся).
5. Остановить `amnezia-telemt`, понаблюдать сутки, потом удалить (копия остаётся).

## Почему не сразу

Это новый модуль Причала (сборка образа, сеть, установка, перенос живых ссылок), а не правка
страницы. Делать по шагам с проверкой каждого: сначала модуль и установка на чистом стенде,
потом перенос на этом сервере.
